# Building the mental string
## Hypothesis
- V1: AI has the potential to generate Behavior Trees that are functionally comparable to human-authored ones, though the conditions and limitations of this capability remain poorly understood.
  
- V2 (more concrete): AI has the potential to generate Behavior Trees that are functionally comparable to those authored by human experts for Autonomous Mobile Robot manipulators, though the conditions under which this capability holds and its limitations across task complexity, ~~environmental variability~~, and manipulation specificity, remain poorly understood.

## To say that the AI can make better BTs they need to be compared
**Claim:** To evaluate if the AI is capable of making a BTs that can be used in the field of robotics we need to evaluate the product made by it to the current standard (expert human making it). 

**Why?:** By evaluating the products from the two approaches, it can be determined if the AI is capable to produce BTs for the robotic industry.

# Metrics
## Functional metrics
Functional metrics are metrics obtained trough observing the performance of the executioner of the BT (in this case - AMR manipulator) such as success/failure rate

The following metrics taken from the Evaluation BT paper: 
- **Use of Resource** - The metric is used to quantify the optimization of resource allocation, management, and utilization of its designated task. One example is the time it takes a BT to complete execution or time for single node execution. 
- **Predictability Distance** - This metric was originally defined by Colledanchise [15,19] for evaluating parallel behaviors. The approach consists of defining a target progress value and then calculating the average deviation between the expected and the actual time at which the action reaches progress closest to the desired value. While primarily utilized in the context of parallel behaviors, it can potentially be used in sequential behavior scenarios as well. (directly taken form paper, do not understand)
- **Success Rate** - Many definitions on success rate depending on context
	- **Desired Behavior Success Rate** - evaluates the extent to which the behavior executed by BT matches the expecting behavior from "behavior oracle"(whatever that means).  In safety accession a success might be the tree preferring avoidance of collision. For correctness, the success is the way/order a task is executed.
		- Defined by the ratio between the correct executions of the inner sub-behaviors over the total expected executions. If tree has 3 major nodes and one of them is for charging, we can evaluate the charging behavior, by evaluating the subtree behavior of that node. 
	- **Single Node Success Rate** - the ratio between the times the node has returned success vs the total executions of the node. refers to the ratio between the number of successful completions of a node n ∈ N (i.e., when it returns Success) and the total number of executions of the node, including both successful and failed attempts, denoted by $\huge{n_S}$ and $\huge{n_F}$ respectively. Mathematically, it is expressed as: $SR_n=\huge{\frac{n_S}{n_S+n_F}}$ 
- **Unsafe state count** - whenever a state leads to irreversible, undesired bahavior. Unsafe state count, measures the amount of unsafe states $U$ are encountered over the total states $T$ during the BT execution: $USC=\huge{\frac{^nU}{^nT}}$ The higher the $USC$  value the higher frequency of unsafe states. Does not correspond directly with success rate, it focuses on the identification and quantification of unsafe states. Can be complimentary safety metric. 
- **Condition check frequency** - quantifies the frequency at which a specific condition node is ticked/evaluated over a given time: $CFF=\huge{\frac{n\_evaluations}{\Delta T}}$ where $n\_evaluations$ is the number of times a the condition node is ticked and $\Delta T$ is the time interval. Higher $CFF$ indicates higher check frequency. Can be used for BT reactivity. 
## Non-functional metrics
Non-functional metrics are the metrics of the static properties of the BT, such as tree depth, condition-to-fallback ratio, action granularity, etc. Anything that is inside the behavior tree after creation.
- **Tree Dimensions** - stuff like height, width, number of nodes.  I will use depth and height interchangeably. 
	- **Height** - total number of edges from the root node to the leaf node in the longest path. 
	- **Width** - maximum number of nodes that exist at any level within the tree structure. DO not understand it completely but it seems it is a range from low-high (from the papers within the EvalBt) 
	- **Number of Nodes** - the amount of nodes within the tree. No distinction between node types
- **Graph edit distance** - The similarity between two graphs, defined by minimum cost of transforming one graph to another by sequence of edit operations, such as add or remove nodes, replace of nodes and edges (although edge is the connection??).
- **Condition-to-Fallback ratio** - Ratio between the condition nodes and the fallback nodes the $CFR$ value is proposed efficiency metric: $CFR=\huge{\frac{num\_conditions}{num\_fallbacks + \epsilon}}$ where $\epsilon$ is infinitesimal value to prevent division by zero. This way zero fallback trees are also considered.
- **Action Granularity** -  The amount of nodes that build certain action. I compared with other tree the environment, condition and values for the action must be exactly the same, as well as the action and action output itself. 

%% # Properties 
## Functional Properties
### Reactivity
**Definition** - A BT is reactive if its decision-making depends only on the current state of the environment, regardless of the execution of the correct action. 
Execution time can be considered general metric for reactivity assessment, as well as condition check frequency. 

**Efficiency** - The degree to which a Behavior Tree performs its designated behavior with minimum consumption of resources. Can be measured assessed with the *Use of resources* metric.

## Map of metrics and properties
In the following maps are shown the metrics and properties separated by they functionality type being functional and non functional. The idea of the maps is to properly show the correlation between metrics and properties and where they can be assessed. The non-functional metrics and properties can be gathered and assessed immediately after the development of the BT. For the functional metrics and properties, the BT needs to be deployed and the outcome data like logs is used for the accession. 

### Functional
| Property    | Quick description                                                  | Metrics used                                                                                                                       |
| ----------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| Reactivity  | How quickly the BT adapts to environmental changes.                | Use of Resources, Condition Check Frequency, Desired Behavior Success Rate, Accuracy for Behavior Usage, Single Node Success Rate. |
| Efficiency  | How well the BT achieves its task with minimal resource use.       | Use of Resources, Predictability Distance.                                                                                         |
| Safety      | Whether the BT avoids unsafe states and hazardous outcomes.        | Unsafe State Count, Desired Behavior Success Rate, Single Node Success Rate, Accuracy for Behavior Usage                           |
| Correctness | Whether the BT follows the intended behavior throughout execution. | Desired Behavior Success Rate, Accuracy for Behavior Usage, Single Node Success Rate.                                              |
| Robustness  | Whether the BT remains correct under disturbances or changes.      | Desired Behavior Success Rate, Accuracy for Behavior Usage, Single Node Success Rate.                                              |

| Metric                        | Quick description                                              | Properties it informs                       |
| ----------------------------- | -------------------------------------------------------------- | ------------------------------------------- |
| Use of Resources              | Measures consumed resources such as time or compute.           | Reactivity, Efficiency                      |
| Predictability Distance       | Measures deviation from a target progress timing.              | Efficiency                                  |
| Desired Behavior Success Rate | Measures match between executed behavior and desired behavior. | Reactivity, Safety, Correctness, Robustness |
| Accuracy for Behavior Usage   | Measures correct execution of sub-behaviors.                   | Reactivity, Safety, Correctness, Robustness |
| Single Node Success Rate      | Measures success of a specific node over all executions.       | Reactivity, Safety, Correctness, Robustness |
| Unsafe State Count            | Measures how often unsafe states are visited.                  | Safety                                      |
| Condition Check Frequency     | Measures how often a condition node is ticked.                 | Reactivity                                  |
### Non-functional
| Property         | Quick description                                 | Metrics used                                             |
| ---------------- | ------------------------------------------------- | -------------------------------------------------------- |
| Modularity       | How decomposed and separable the BT structure is. | Action Granularity, Tree Dimensions, Graph Edit Distance |
| Interpretability | How understandable the BT is to a human.          | User Study, Action Granularity, Tree Dimensions          |

| Metric                      | Quick description                                          | Properties it informs                                                       |
| --------------------------- | ---------------------------------------------------------- | --------------------------------------------------------------------------- |
| Action Granularity          | Degree of behavioral decomposition into smaller actions.   | Modularity, Interpretability                                                |
| Tree Dimensions             | BT size/shape measures like height, width, and node count. | Modularity, Interpretability, and sometimes Efficiency as a structural hint |
| Graph Edit Distance         | Similarity between two BT structures.                      | Modularity, sometimes Correctness as a structural comparison tool           |
| User Study                  | Human-rated understanding of the BT.                       | Interpretability                                                            |
| Condition-to-Fallback Ratio | Structural ratio of condition nodes to fallback nodes.     | Efficiency                                                                  |
